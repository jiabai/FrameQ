ASR 模型下载失败排查报告

FrameQ 桌面端 · 单机（Windows）环境相关问题分析 · 2026-08-15

核心结论：模型下载链路本身在别的机器上都正常，失败几乎可以锁定在「这台机器的环境」与下载链路的三个接口点上：① 继承的环境变量（代理 / MODELSCOPE_DOMAIN）→ ② 网络链路（运营商 / Wi-Fi / IPv6 / 杀软防火墙）→ ③ 本地文件系统（安全软件锁文件、磁盘空间、权限）。最快的定位方式不是猜，而是让朋友用 v0.3.2 的「诊断导出」功能导出最近 7 天的诊断 ZIP，里面带分类错误码（network / tls / proxy / http / filesystem / integrity），一次就能锁定根因。

1. 下载链路全景

ASR 模型下载由一条跨前后端的链路完成，每一步都可能被「单机环境」影响：

① 前端触发
应用内点击下载 / 首次提交任务自动下载（app/src/features/asrModel/useAsrModelDownload.ts），UI 在 45 秒无进度时显示「下载进度暂时没有变化」横幅（modelDownloadState.ts，阈值 45s，仅提示不终止）。
② Tauri 命令启动 worker 进程
Rust 侧 download_asr_model 命令用内置 python.exe 启动 worker 子进程（app/src-tauri/src/asr_model.rs），传入 FRAMEQ_MODEL_DIR 等变量。子进程继承桌面进程的全部环境变量（process_io.rs，仅移除 LLM 相关旧 key）——这是代理类问题的入口。
③ Python worker 调 modelscope
默认走官方 ModelScope snapshot_download（worker/frameq_worker/model_download.py），下载 SenseVoiceSmall（约 900MB+）与 VAD 模型；ONNX 版额外做 8 个文件 SHA256 校验。
④ watchdog 兜底
模型下载专用策略：10 分钟无进度 → idle 超时终止；总时长超 4 小时 → 绝对超时终止（worker_runtime/runner/watchdog.rs）。终止后 UI 分别提示「长时间没有新的进展」/「超过最长运行时间」。
⑤ 落地校验
下载完写 MODEL_VERSION.txt、迁移缓存布局、校验关键文件存在（ONNX 版含 SHA256），失败则任务返回失败，UI 提示「模型下载失败，请检查网络后重试」或「模型下载未完成」。

2. 代码里发现的「环境敏感点」

worker 子进程继承桌面全部环境变量

Rust 用 Command::new(...).envs(...) 启动 python worker，只删除 LLM 旧 key（process_io.rs），其余全部继承。Python 侧 requests 会读取 HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY；modelscope 的 get_domain() 会优先读 MODELSCOPE_DOMAIN 环境变量（modelscope hub/utils/utils.py），INTRA_CLOUD_ACCELERATION_REGION 也会改变下载源。任何一台机器上残留这些变量（加速器、代理软件、其他 AI 工具设置的），下载行为就会与别的机器不同。

TLS 走 Python 自带证书库，不经系统证书

worker 用打包的 Python + certifi 校验证书。如果机器上有安全软件/企业代理做 HTTPS 中间人（MITM），其证书不在 certifi 信任列表里 → tls_verification_failed。系统时间错误也会导致证书校验失败。

下载落盘与「改名-替换」模式怕杀软锁文件

modelscope 边下边写 ._____temp 临时目录再落盘；自定义归档走 tempfile + os.replace。360/火绒/电脑管家等实时防护可能在写入时锁文件或把 model.pt（900MB）当可疑文件处理 → permission_denied / filesystem_io_failed，或下载「成功」但文件被删 → 缓存校验失败。

超时窗口对慢网偏紧

idle 10 分钟无任何字节进展即被杀。Wi-Fi 不稳、运营商到 modelscope 链路差、IPv6 优先导致握手挂起时，表现就是「下载到一半提示超时」。绝对 4 小时对应约 62KB/s 的平均速度下限。

3. 假设排名（按「只在这台机器出现」的概率）

排名假设代码依据诊断特征验证方法
1 代理 / 加速器 / MODELSCOPE_DOMAIN 环境变量残留，请求被导向失效代理或错误域名 环境继承（process_io.rs）；modelscope 读 MODELSCOPE_DOMAIN / 代理变量 proxy_* / connection_failed / connection_timeout / dns_resolution_failed cmd 里 set HTTPS_PROXY、set MODELSCOPE_DOMAIN；关掉加速器后重试
2 安全软件 / 防火墙拦截：拦 python.exe 联网，或下载中锁文件 / 删文件 modelscope 临时目录落盘 + os.replace；校验在下载后 permission_denied / filesystem_io_failed / cache_invalid 临时退出 360/火绒/管家重试；或加白 FrameQ 目录
3 网络链路问题：Wi-Fi 不稳、运营商到 modelscope.cn 慢、IPv6 优先握手挂起 watchdog idle 10 分钟即终止（watchdog.rs） connection_timeout / 提示「长时间没有新的进展」 手机开热点重试；ping modelscope.cn；关 IPv6
4 TLS 校验失败：MITM 代理 / 杀软 SSL 扫描 / 系统时间错误 worker 用自带 certifi，不读系统证书库 tls_verification_failed / tls_handshake_failed 核对系统时间；关杀软 HTTPS 扫描；诊断 ZIP 看 exception_type
5 磁盘空间不足 / AppData 权限异常 / TEMP 不可写 下载写 %LOCALAPPDATA% 与 %TEMP% disk_full / permission_denied 查 C 盘剩余空间（需 >2GB）；检查 AppData 写入权限
6 上次中断残留的半截缓存 / 损坏的临时目录，反复失败 modelscope 缓存按文件存在性判断，可能跳过重下；validate 只查存在不查完整性（PyTorch 版） cache_invalid / archive_invalid / 提示「模型下载未完成」 删除 %LOCALAPPDATA% 下 FrameQ 的 models 目录重试
7 低概率：超长用户名路径（MAX_PATH）、极慢网络超 4 小时、旧系统 TLS 支持 模型路径 ~100 字符，通常不触发 260 限制 filesystem_io_failed / executionTimeout 视诊断结果而定

4. 让朋友立刻能做的定位动作

第一步：导出诊断（最快、最准）

确认朋友端版本 ≥ v0.3.2（诊断导出是 v0.3.2 加入的），在「设置」或「关于」页面找到诊断导出入口，导出最近 7 天的诊断 ZIP 发回来。ZIP 里包含：

  • asr-model-download.log — ASR 下载专用 stderr 兜底日志
  • 分类诊断事件 — operation=download_asr_model + category（network / tls / proxy / http / filesystem / integrity / dependency / unexpected）+ phase + exception_type + os_error_code
  • desktop 日志（worker.download_asr_model.*）

诊断事件由 worker/frameq_worker/diagnostic_events.py 在下载失败时自动生成并落盘，7 天保留窗口。

第二步：对照朋友看到的提示文案
UI 提示对应根因方向
「模型下载失败，请检查网络后重试」大多数网络 / TLS / 代理 / HTTP / 文件系统失败（需要诊断码细分）
「模型下载长时间没有新的进展，已停止」10 分钟无进度 → 卡死型网络问题（代理失效、Wi-Fi、IPv6）
「模型下载已超过最长运行时间」极慢网络（<62KB/s 平均）或反复重试耗尽 4 小时
「模型下载未完成，请稍后重试」下载结束但缓存校验不过 → 文件被删 / 半截 / 损坏
「下载进度暂时没有变化」（横幅）45 秒无进度提示，非终止，仅提示网络慢
第三步：立即可试的绕过方案
  • 关闭 VPN / 加速器 / 代理软件（或切换节点）后重试；cmd 里 set 查看 HTTP(S)_PROXY、MODELSCOPE_DOMAIN 是否有残留值
  • 临时退出 360 / 火绒 / 腾讯管家等安全软件重试；不行就给 FrameQ 的 python.exe 与数据目录加白名单
  • 手机开热点连一次，排除家庭路由器 / 运营商链路问题
  • 检查 C 盘剩余空间（≥2GB）与系统时间是否准确
  • 删除 %LOCALAPPDATA%\ 下 FrameQ 的 models 目录（清掉半截缓存）后重试
  • 更新到最新版本（v0.3.2 及以上）

5. 代码改进建议（review 输出）

#问题建议
1 下载失败时 UI 只有一条通用文案「模型下载失败，请检查网络后重试」，诊断码不展示给用户 把 diagnostic category/code 映射为具体提示（代理连接失败 / 证书校验失败 / 磁盘空间不足等），用户可自助判断；至少把诊断事件透出到「查看详情」
2 worker 继承全部环境变量，代理 / MODELSCOPE_DOMAIN 残留会静默改变下载行为 下载命令显式清理或固定 proxy 相关变量；诊断 ZIP 中记录「哪些敏感环境变量被设置」（只记 key 不记值），单机问题一次定位
3 PyTorch 版缓存校验只查文件存在，不查大小 / 哈希，半截文件会被当作成功 复用 ONNX 版的校验思路：对 model.pt 增加文件大小（或抽样哈希）检查
4 idle 10 分钟对部分慢网偏紧，且失败后无自动重试 进度事件已按 chunk 上报，可考虑「慢但有进展」时放宽 idle 判定；或失败后提示一键重试

6. 根因确认（2026-08-15 13:29 更新，基于朋友机器导出的诊断日志）

最新结论：不是网络问题，是 Python worker 进程在启动（import 阶段）快速崩溃，从未进入下载逻辑。
三份日志交叉验证的证据
日志关键证据含义
frameq-desktop.log12+ 次尝试全部 5~8 秒退出，全部 unstructured_failure快速崩溃而非网络慢/超时（模型下载正常需几十分钟）
asr-model-download.log零条结构化诊断事件，仅脱敏 stderr traceback（[traceback]/[text]/[exception]）异常发生在下载代码 try 块之外 = import 阶段（诊断回调已接通，正常失败必有 structured 记录）
asr-model-download.log无任何 network/connection/timeout/proxy/tls/http/dns/permission/disk 关键词排除网络、代理、TLS、磁盘满类别
diagnostics.json版本 0.3.2、cache_status=missing、三文件均 included数据完整可信，模型从未下载成功
最可能的具体原因（按概率）
  1. 安全软件（360/火绒/管家）隔离或删除了安装目录文件（.pyd/.dll/.py）— 打包 Python 应用的经典事故，完美解释「只在这台机器」
  2. 安装包解压不完整 / 安装损坏（安装时被安全软件拦截）
  3. 缺 Microsoft Visual C++ 运行库（原生扩展 DLL 加载失败）
行动计划
  • 先确认：朋友用 FrameQ 转写视频是否也失败（是则 100% 坐实 worker 环境问题）
  • 卸载后重新下载安装包重装，安装/运行时对安全软件弹窗选「允许」，并把 FrameQ 安装目录加白名单
  • 安装微软官方 Microsoft Visual C++ Redistributable 2015-2022 x64
  • 仍失败则运行 frameq-asr-diagnostic.bat（先打开 FrameQ 再双击），把桌面生成的 frameq-err.txt 发回——该文件未脱敏，可精确定位崩在哪一行、哪个模块
