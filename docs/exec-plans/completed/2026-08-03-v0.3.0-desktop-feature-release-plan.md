# FrameQ v0.3.0 Desktop Feature Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare one verified v0.3.0 release commit for the completed local-media import, selectable ONNX ASR with on-demand download, streaming ONNX VAD, transcript dissection, and bundled ONNX runtime integrity work, then create the tag and publish the Draft Release after explicit approval. The release-prep diff (Tasks 1–4) must be reviewed and approved before Task 5 (tag + publish) starts.

**Architecture:** Release preparation changes metadata, the version-drift test expectation, release notes, and governance indexes only. Runtime behavior and the desktop-worker contract are unchanged from `main`; the bundled worker is already on `main`. GitHub-hosted platform builds remain behind the later tag-triggered Draft Release checkpoint.

**Tech Stack:** Node.js release scripts, npm, TypeScript, Vitest, Tauri/Rust, Python/uv/pytest/Ruff, GitHub Actions, Markdown governance documents.

## Decision Log

- Decision: Use `0.3.0` (minor) instead of `0.2.18` (patch). Rationale: v0.2.17 → main ships
  user-visible new capabilities (local-media import, transcript dissection, selectable ONNX ASR +
  on-demand download) and ASR failure-semantics changes (streaming ONNX VAD with terminal block
  failure replacing whole-audio fallback). semver at 0.x treats backward-compatible feature
  additions as minor. Date/Author: 2026-08-03, User + Codex.
- Decision: Do not re-run v0.2.17 broad-release reliability failure-injection evidence (atomic
  persistence, worker watchdog, server auth/quota concurrency, server production operations).
  Rationale: those gates were accepted on 2026-07-25 with full local, hosted CI, and production
  deployment evidence; v0.3.0 does not change atomic persistence, watchdog, server auth/quota, or
  server production-operations code paths in a way that would invalidate that evidence.
  Date/Author: 2026-08-03, Codex.
- Decision: Keep tag creation, hosted Draft generation, and public publication as separate approval
  checkpoints after the release-prep diff is reviewed. Rationale: each is an externally visible
  checkpoint that follows review of the release-prep diff. Date/Author: 2026-08-03, User + Codex.
- Decision: Do not advertise macOS local-media import, macOS ONNX VAD streaming, or macOS watchdog
  runtime as verified. Rationale: Windows evidence is recorded; macOS runtime remains an explicit
  residual risk that must be disclosed in release notes. Date/Author: 2026-08-03, Codex.
