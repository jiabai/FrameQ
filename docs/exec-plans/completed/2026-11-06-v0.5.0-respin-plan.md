# FrameQ v0.5.0 Same-version Re-release Plan

This ExecPlan is a living document. The sections Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds.

## Purpose / Big Picture

Re-publish the desktop release under the existing `v0.5.0` version after fixing the "Polish Transcript" too-long notice. The first `v0.5.0` build was published 2026-11-05 23:51 +08:00. The fix landed on `main` in `6315846`, `3d68fc0`, and `86a255c`. Reusing the version leaves the six version sources and `site/src/consts.ts` untouched. The updater will not offer the new build to anyone who already installed the first one, so both release notes and the ledger must state that a manual reinstall is required.

## Surprises & Discoveries

- The first `v0.5.0` release already has real downloads (two DMGs twice each, the Windows installer once), so this re-release affects actual users.
- Deleting the release removes all 8 assets, including the three `frameq-pytorch-runtime-*.zip` components whose URLs are version-bound. `desktop-release.yml` uploads all three on every tag push (lines 109, 180, 250), so the new build restores them.
- The local Rust suite cannot complete its real-filesystem cases in this environment: 54 failures are permission errors rather than assertion regressions, they persist on a single-case rerun, and the hosted Native ProcessSupervisor job is green on `86a255c`. The re-release changes no Rust source.

## Decision Log

- Decision: Re-publish under `v0.5.0` instead of incrementing the version. Rationale: the user chose it because the first build had been published only hours earlier. Date/Author: 2026-11-06, User.

- Decision: Point the new tag at `86a255c`. Rationale: it carries every fix; later documentation commits do not affect the installer. Date/Author: 2026-11-06, Codex.
- Decision: State the manual-reinstall requirement in both release notes and `TASKS.md`. Rationale: the updater does not push a build with the same version. Date/Author: 2026-11-06, Codex.

## Outcomes & Retrospective

FrameQ v0.5.0 is re-published at https://github.com/jiabai/FrameQ/releases/tag/v0.5.0 with the tag at `86a255c`. The reviewed release body is live, all eight assets are uploaded, both updater signatures match, the three installer URLs answer `206`, and the marketing site, `TASKS.md`, this plan and both indexes agree on the same-version re-release. The transcript-polish too-long notice now shows the length limit in all three locales.

Not run and residual risk: `macos-intel-acceptance.yml` needs a manual dispatch and was not run for this tag. The local `cargo test` suite reports 54 permission-related failures in real-filesystem cases; no Rust source changed, and the hosted Native ProcessSupervisor job is green on `86a255c`. macOS graphical interaction, Gatekeeper and permission prompts, specialized WebView canaries and the complete public signed-update path remain unverified. Anyone who installed the first `6857d97` build must reinstall manually, because the updater does not offer a build with the same version.
