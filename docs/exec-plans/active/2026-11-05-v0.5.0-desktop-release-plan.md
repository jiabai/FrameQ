## Surprises & Discoveries

- `CARGO_PKG_VERSION` is both the PyTorch runtime component directory (`data_storage_root/runtime/pytorch/<version>`) and its release URL (`releases/download/v<version>/frameq-pytorch-runtime-<target>.zip`). Upgrading to v0.5.0 invalidates the v0.4.3 component; users on the optional PyTorch model must download the roughly 140 MB component again. The default ONNX model is unaffected. This is recorded in both release notes.
- The site release-notes frontmatter `date` is set to the preparation date `2026-11-05`. It must be checked against GitHub `publishedAt` before the site is deployed.
- The remaining `0.4.3` strings are historical ledger entries, the v0.4.3 release notes, the installer filename in the release-readiness evidence, third-party lock entries, and an arbitrary non-empty fixture string in `app/src-tauri/src/data_storage_validation.rs`. That fixture is validated for presence only and carries no equality assertion against the application version, so it stays unchanged.

## Idempotence and Recovery

All preparation edits are source-controlled and reversible with file edits. Do not delete or re-tag an existing public release. If the hosted release build fails before publication, fix the source on `main`, delete the draft release and the tag, then tag the corrected commit.
