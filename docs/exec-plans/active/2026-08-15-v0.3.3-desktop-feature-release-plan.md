# FrameQ v0.3.3 Desktop Feature Release Plan

## Goal

Publish the merged VC++ runtime self-check / import-stage diagnostics work and the stability
hardening batch as v0.3.3 without moving or replacing the already-published v0.3.2 tag.

## Scope

- Include the merged VC++ runtime batch (commits `5d296d9` → `0c131f1`): app-local VC++
  2015-2022 runtime DLL bundling on Windows, Rust pre-flight runtime self-check with the closed
  `ASR_MODEL_RUNTIME_MISSING` error, import-stage structured diagnostic fallback, and
  three-language runtime-missing guidance.
- Include the merged stability hardening batch (commits `03579d8`, `5376807`): ONNX staging
  leftover cleanup, streamed custom-archive download with timeout/retry/size-cap, disk-space
  preflight, unified runtime preflight for all worker lanes, torch-magic cache validation,
  desktop log rotation, throttled progress events, and the canonical↔packaged worker CI sync
  gate.
- Keep v0.3.2 behavior and release notes as historical record.
- Do not package ASR weights, LLM keys, cloud models, or user-private configuration.
- No server changes are included; hosted Server CI is not a release gate for this version (the
  shared server suites stay green locally as a regression check only).

## Version Baseline

Current version sources all read `0.3.2`: `app/src-tauri/tauri.conf.json`,
`app/package.json`, `app/src-tauri/Cargo.toml`, plus the release-version guard
(`scripts/check-release-version.mjs`) and its version test.

- Byte sync: `node scripts\verify-packaged-worker.mjs` after refreshing packaged resources.

**Validation:** each gate recorded in Progress with evidence.

## Task 4: Clean-Windows smoke test

**Goal:** Prove a Windows machine without the VC++ 2015-2022 redist can download/use the ASR
model out of the box.

**Implementation notes:**

- Hosted Windows runners include the VC++ runtime, so this must run on a Windows VM or a
  machine without the VC++ 2015-2022 redist installed (uninstall the redist first if needed).
- Install the v0.3.3 package, start the app, trigger the ASR model download, and confirm
  download completes and transcription is usable.
- If the download fails with `ASR_MODEL_RUNTIME_MISSING`, that is a packaging regression; if the
  machine is not available, record as residual and rely on the DLL assertions plus the unit-test
  matrix (the `vc_runtime` AppLocalMissing/SystemMissing branch tests).

**Validation:** manual evidence recorded in Progress; unavailable machine recorded as residual.
