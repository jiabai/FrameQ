# FrameQ v0.3.1 Desktop Feature Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare one verified v0.3.1 release commit for the completed Web user dashboard,
server-page i18n, Inspiration Profile v2 / per-run generation preference boundary, progress-aware
retry watchdog, desktop worker contract v7 with dissection source status, and transcript
provenance stability fix work, then create the tag and publish the Draft Release after explicit
approval. The release-prep diff (Tasks 1–4) must be reviewed and approved before Task 5
(tag + publish) starts.

**Architecture:** Release preparation changes metadata, the version-drift test expectation,
release notes, and governance indexes only. Runtime behavior and the desktop-worker contract are
unchanged from `main`; the bundled worker is already on `main`. **Unlike v0.3.0, this release
contains server code changes already on `main`** (Web dashboard + i18n), so server-specific
hosted CI, migration preflight/restore smoke, and production `secureCookies` deployment
verification are mandatory before publication.

**Tech Stack:** Node.js release scripts, npm, TypeScript, Vitest, Tauri/Rust, Python/uv/pytest/
Ruff, Prisma migrations, GitHub Actions, Markdown governance documents.

## Decision Log

- Decision: Use `0.3.1` (patch), chosen by the user on 2026-08-05, replacing the initially
  proposed `0.4.0` (minor). Rationale: v0.3.0 → main ships user-visible new capabilities (Web
  user dashboard, server-page i18n, Inspiration Profile v2 per-run preference boundary) and a
  desktop-worker contract change (contract v7 + dissection source status), which would justify a
  minor bump under 0.x semver; the user instead opted for a patch-level release for this batch.
  The distribution, billing, and trust model are unchanged. Date/Author: 2026-08-05,
  User + Codex.
- Decision: Include server changes (Web dashboard + i18n) in this release and therefore require
  server-specific gates (hosted server CI, migration status/preflight, copied-DB restore smoke,
  production `secureCookies` verification on `frameq.8xf.pro`). Rationale: the dashboard and i18n
  are user-visible server capabilities merged on `main`; publishing them is part of the release
  intent, and EXECUTION_GATES mandates hosted CI + migration/preflight/restore evidence for
  production server changes. Date/Author: 2026-08-05, Codex.
- Decision: Exclude the Web marketing site (`site/`) from this release. Rationale: it is an
  independent Astro static distribution channel, merged on `main` without a version number, and
  is not bundled into any desktop/server artifact. Date/Author: 2026-08-05, Codex.
- Decision: Keep tag creation, hosted Draft generation, and public publication as separate
  approval checkpoints after the release-prep diff is reviewed. Rationale: each is an externally
  visible checkpoint that follows review of the release-prep diff. Date/Author: 2026-08-05,
  User + Codex.
- Decision: Do not re-run v0.2.17 broad-release reliability failure-injection evidence (atomic
  persistence, worker watchdog, server auth/quota concurrency, server production operations).
  Rationale: those gates were accepted on 2026-07-25 with full local, hosted CI, and production
  deployment evidence; v0.3.1 does not change those code paths in a way that would invalidate
  that evidence (the progress-aware watchdog extends, rather than replaces, the accepted
  watchdog boundary). Date/Author: 2026-08-05, Codex.
- Decision: Do not advertise macOS runtime or native packaged UX as verified. Rationale:
  Windows evidence is recorded; macOS runtime and packaged-launch evidence remain explicit
  residual risks that must be disclosed in release notes. Date/Author: 2026-08-05, Codex.
- Decision: Treat `cargo test` and Tauri `--no-bundle` as local-environment residuals for this
  release-prep instead of release blockers. Rationale: rustc repeatedly crashes with
  `0xc0000409 STATUS_STACK_BUFFER_OVERRUN` when compiling large crates (rustls, tauri-macros,
  cargo_metadata) on this host after the target clean, despite `RUST_MIN_STACK` and the existing
  `jobs = 2` config; the code is unchanged since v0.3.0 (233 passed recorded 2026-08-03 on this
  host), so the crashes are environmental (4 GB pagefile / security-agent interference), not
  regressions. The tag-triggered Desktop Release workflow compiles and tests on clean GitHub
  runners and is the authoritative Rust verification. Date/Author: 2026-08-05, Codex.
