# v0.6.1 LLM BYOK Implementation Plan

Status: **design confirmed, no code written yet** (2026-11-10). Waiting for the user's go-ahead.

## Boundary

- v0.6.1 features continue to be developed on the `0.6.0` version number. **No bump, no tag, no Release, no site deployment** in this plan.
- `site/` is entirely gitignored; this feature does not touch it.
- No server-side Admin changes, no production deployment, no schema migration of existing user data.

## Goal

Add a second LLM configuration source. Users can add their own OpenAI-compatible endpoints in Settings (provider preset + free-form base URL/model, API Key, test connection, multiple saved configurations with one active). Default stays Locus-managed (login + server checkout + AI Credit). Keys live in the OS credential store and never touch files, logs, argv, progress events or diagnostic exports.

## Non-goals

Server-side BYOK proxying, WebView-side direct API calls, plaintext `.env` keys, anysearch custom credentials, automatic model discovery, automatic fallback between sources, release actions.

## Preconditions (TDD discipline)

Every step below is **RED → GREEN → REFACTOR**: write the failing test first, run it and observe the failure, implement the minimum, rerun until green. Code written before a failing test is deleted. Each step ends with its own gate command; do not batch unrelated steps into one commit.

Work on an isolated branch/worktree; confirm a clean test baseline before Step 0.

## Surprises & Discoveries

- `migrate_settings_schema()` (`settings.rs:376-399`) rewrites `APP_ASR_MODEL` whenever the schema version differs, so the planned `APP_SETTINGS_SCHEMA_VERSION` bump 2 → 3 would have silently reset every existing install's ASR model. BYOK uses its own `llm_providers.json`, so the .env schema stayed at 2; spec, design doc and Step 2 were corrected.
- The contract traversal test (`desktopWorkerContract.test.ts`) asserts that no key name contains `timeout` / `deadline` / `watchdog`. The probe stdin therefore carries only the four closed fields `{base_url, api_key, model, provider}`; the 15 s timeout is a worker-side constant, not a cross-language field.
- Bumping `contractVersion` 11 → 12 needed **four** synchronized edits, not two: the JSON, `worker/worker_core/desktop_contract.py`, `app/src-tauri/src/lib.rs` (`#[cfg(test)] DESKTOP_WORKER_CONTRACT_VERSION`) and `scripts/tests/build-installer.test.mjs`. The last two surfaced only in the full gate run.
- `cargo test --lib` hung in the Tauri build script again (same as the 2026-11-09 rename). Clearing `target/debug/build/app-*`, then compiling with `--no-run` and running the test binary directly, is reliable.
- The frontend uses six commands, not the seven in the earlier draft (`get_llm_source` was dropped because `list_llm_providers` already returns `source`). Rust matches the six frozen commands.
- Under parallel load, one app test file failed at file level (all 1576 cases still passed), the app build once hit an ESM loader error, node scripts briefly reported 4 failures, and the Rust `contract` filter reported 1 failure. All passed on isolated / single-threaded reruns (contract 21/21); the only genuine script failure was the hardcoded v11 contract version.
- Three `#[cfg(test)]`-only items (`InMemorySecretStore`, the legacy `build_worker_command_spec` wrapper, the facade account import) produced dead-code warnings in the release build; gating them removed all warnings.

## Outcomes & Retrospective

Implemented on branch `feat/llm-byok-v0.6.1` with RED→GREEN at each step. Default behaviour is unchanged: Locus-managed LLM (login + server checkout + AI Credit). BYOK is an opt-in second source whose keys live only in the OS credential store; Rust injects five `APP_LLM_*` variables into AI worker commands and still strips them from non-AI commands. Draft keeps server-managed anysearch and is rejected with `AI_DRAFT_REQUIRES_LOGIN` when logged out.

**Step 11 remains blocked** on a real API key. Manual steps: Settings > Models → switch to "我自己的 API" → add a preset (e.g. SiliconFlow) with a real key → press "测试连接" → set active → generate a summary and confirm the server AI Credit counter did not move; repeat with draft while logged out to see the localized warning; finally inspect `desktop.log` and a diagnostic ZIP for key material.

No version bump, tag, Release or site deployment was done.
