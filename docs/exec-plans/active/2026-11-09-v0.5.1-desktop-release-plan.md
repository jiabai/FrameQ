# FrameQ v0.5.1 Desktop Release Plan

This ExecPlan is a living document. The sections Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds.

## Purpose / Big Picture

Prepare and publish FrameQ v0.5.1, the first desktop release after the re-tagged v0.5.0. Ship set covers three desktop-visible changes accumulated on `main` since the v0.5.0 tag: a fixed execution budget for the `yt-dlp` download child process, Douyin share-page retries becoming visible in exported diagnostics, and a Windows installer preflight for free space and writability with a step log. It also carries the MarkdownSplitter child-process test fix that made two earlier release gates need a rerun. Publication target is tag `v0.5.1`, with the ledger, plan indexes, and marketing site synchronized.

## Surprises & Discoveries

- The v0.5.0 release notes list "YouTube 与 B 站走 `yt-dlp` 的下载仍没有外部超时包装" under 已知局限. That limitation no longer holds after `3f0bdbb`, so the v0.5.1 notes must drop it instead of repeating it.
- `CARGO_PKG_VERSION` again acts as the PyTorch runtime component identity (`app/src-tauri/src/runtime_component.rs:46-53`), so the version bump invalidates the component cached by v0.5.0 users and the notes must repeat the roughly 140 MB re-download caveat.

## Decision Log

- Decision: Use `v0.5.1`. Rationale: the ship set is three backward-compatible fixes plus one test fix, with no product-surface removal or contract change, so a patch bump matches the change class. Date/Author: 2026-11-09, User authorized the release after the ship set was summarized.
- Decision: Include the installer change in this release. Rationale: it only affects the NSIS installer build produced by this tag, and shipping it separately would require a second full three-platform build of the same version line. Date/Author: 2026-11-09, WorkBuddy.
- Decision: Keep the server-side WeChat Pay removal out of the desktop notes. Rationale: it changes no desktop behavior and the server has no independent version; it is already recorded in the server ledger. Date/Author: 2026-11-09, WorkBuddy.

## Validation and Acceptance

Version consistency, local and hosted gates, all three release jobs, the asset name set, updater signatures, the release body, the ledger and plan indexes, and the public site must all be verified with recorded evidence before this plan moves to `completed/`.

## Idempotence and Recovery

Source-controlled edits remain reversible with file edits. Do not delete or re-tag a published release. If the hosted release build fails before publication, fix the source on `main`, delete the draft release and the tag, then tag the corrected commit. Site deployments keep a timestamped remote webroot backup.
