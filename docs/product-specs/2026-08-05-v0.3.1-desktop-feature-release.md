# FrameQ v0.3.1 Desktop Feature Release Spec

## Status

Proposed on 2026-08-05 for release preparation. The release-prep diff (Tasks 1–4 of the
companion ExecPlan) must be reviewed and approved before Task 5 (tag + publish) starts. v0.3.0
remains the current Latest stable release until v0.3.1 publishes. All v0.2.17 broad-release
reliability acceptance (atomic persistence, worker watchdog, server auth/quota concurrency,
server production operations) remains inherited. Unlike v0.3.0, this release **includes server
code changes**, so server-specific hosted CI, migration preflight/restore smoke, and production
deployment verification are mandatory gates (see Release Flow).

## Release Intent

FrameQ v0.3.1 is a stable patch release for the existing personal-development, small-user, and
open-source distribution model. It packages the completed Web user dashboard, server-page i18n,
Inspiration Profile v2 / per-run generation preference boundary, progress-aware retry watchdog,
desktop worker contract v7 with dissection source status, and transcript provenance stability
fix as one compatible desktop/worker/server release. The version is a patch bump chosen by the
user for this batch (the desktop-worker contract version is internal to the 0.x pre-1.0 line);
the distribution, billing, and trust model are unchanged.

## Included Scope

- **Web user dashboard (server).** Browser-side per-user dashboard at `GET /dashboard` with
  email-OTP cookie-session login (reusing the `desktop_login` OTP purpose and the Admin Web
  session model), account-and-quota content (email, entitlement expiry, AI Credit limit/used/
  remaining/reset, `can_process`, `can_generate_ai`, bound activation-code prefix), desktop
  login success panel with Web Dashboard entry, and web/desktop session independence. The OTP
  row is consumed exactly once across desktop-ticket and web-session paths. Desktop deep-link
  login contract (`{ ticket, redirect_url }`) unchanged.
- **Server-page i18n (server).** Per-page language switcher on `/login`, `/dashboard`,
  `/admin/login`, and `/admin` toggling `zh-CN` (default) and `en` via a non-sensitive `lang`
  cookie; new `server/src/i18n.ts` module. No `zh-TW` server locale in this version.
- **Inspiration Profile v2 / per-run generation preference boundary (desktop).** Profile v2 keeps
  only six long-term background fields; expression style and avoid directions belong to the
  current per-run six-step generation preference. Tauri performs a local atomic v1→v2 migration
  of the app-local preferences file with a one-time edit-only seed; retry snapshots close at the
  JSON/Rust/Python boundary; historical task snapshots remain unchanged.
- **Progress-aware RetryInsights watchdog (desktop).** Retry AI jobs register progress events and
  report dissection-call progress; the watchdog applies a 30-minute validated-idle deadline and a
  90-minute absolute deadline with closed progress protocol.
- **Desktop worker contract v7 + dissection source status (desktop).** Desktop-worker contract
  rises to version 7; AI result detail surfaces the dissection source status (e.g. stale-source
  handling) through the closed result protocol.
- **Transcript provenance stability fix (worker).** Transcript reads switch to raw UTF-8 bytes
  before hashing so CRLF transcripts keep `sourceTranscriptSha256`/chunk hashes matching on-disk
  bytes (provenance stability for dissection).
- **Governance-only module splits and docs** contained in the v0.3.0→main range that carry no
  user-visible behavior change are included as part of the release commit surface.

## Excluded Scope

- **Web marketing site (`site/`).** The Astro static site is merged on `main` but is an
  independent distribution channel, is not bundled into any desktop/server artifact, and ships
  without a version number. It is out of scope for this release flow.
- **`zh-TW` server locale** and **`Accept-Language` fallback** remain deferred (require reviewed
  Traditional Chinese copy per `docs/DESIGN.md`).
- **Inspiration-to-draft (`生成文字稿`)** remains design/documentation work; not in this release.
- No ASR model weight, LLM credential, payment credential, user configuration, log, task, or
  user artifact is added to an installer; the installer remains lightweight and the core ASR
  model is downloaded only when a verified task is submitted and the selected model is missing.
- No Linux artifact, no Universal macOS binary, no App Store review, no Apple notarization, no
  Developer ID signing.
- No WeChat payment enablement; `WECHAT_PAY_ENABLED` stays default off.

## Supported Artifacts

- Windows x64 NSIS installer, updater signature, and `latest.json`.
- macOS Intel (`x86_64`) DMG.
- macOS Apple Silicon (`aarch64`) DMG.
- No Linux artifact or Universal macOS binary.

## macOS Trust Boundary

The ad-hoc-signing policy is unchanged. Both macOS app bundles must pass bundled-runtime, Deno,
and `codesign --verify --deep --strict` checks on GitHub-hosted macOS runners, but they are not
Developer ID signed or notarized. Release notes must place the Gatekeeper disclosure before
download links and must not imply App Store review, notarization, or silent enterprise deployment.

## Release Flow

1. Synchronize all five desktop version sources at `0.3.1` and keep the automated drift test
   (`scripts/check-release-version.mjs` and `scripts/tests/release-version.test.mjs`) GREEN at
   the new version.
2. Run the complete local release gates on the release-prep diff and record exact evidence
   (script tests, app tests/lint/build, Rust tests/rustfmt, worker tests/Ruff, server
   tests/build, governance validation, diff checks, refreshed packaged-worker SHA-256 equality,
   and Tauri `--no-bundle`).
3. **Server gates (new for this release):** run the hosted server CI
   (`.github/workflows/server-ci.yml`), the Prisma migration status/preflight, and a copied-DB
   restore smoke; verify the production deployment on `frameq.8xf.pro` sets `secureCookies` so
   `frameq_user_session`/`frameq_user_csrf`/admin cookies carry the `Secure` flag (Web dashboard
   residual risk from its ExecPlan).
4. Do not create a tag, run Desktop Release, or publish a GitHub Release until the release-prep
   diff is reviewed and approved.
5. Commit and push the verified release changes only after review, then create annotated tag
   `v0.3.1` as a separate action.
6. Let the tag-triggered Desktop Release workflow create a Draft Release and build all three
   platform artifacts from one tagged commit.
7. Inspect artifact names, updater metadata, bundled runtime imports, Deno smoke, macOS codesign
   output, and release notes before publishing the Draft as a stable non-prerelease release.

## Acceptance Criteria

- `app/package.json`, `app/package-lock.json`, `app/src-tauri/Cargo.toml`,
  `app/src-tauri/Cargo.lock`, and `app/src-tauri/tauri.conf.json` agree on `0.3.1`.
- `scripts/tests/release-version.test.mjs` asserts `0.3.1` and the explicit version checker
  reports consistent sources.
- App tests, lint, production build, Rust tests/rustfmt, worker tests/Ruff, server tests/build,
  script tests, documentation validation, and diff checks pass.
- A Tauri no-bundle release build succeeds with a freshly synchronized packaged worker.
- Hosted server CI passes; migration status/preflight and copied-DB restore smoke pass; the
  production deployment reports `secureCookies` enabled.
- The Draft Release jobs succeed for Windows x64, macOS Intel, and macOS Apple Silicon, and
  every uploaded artifact reports version `0.3.1`.
- macOS release acceptance records native runtime status truthfully; unavailable manual evidence
  remains an explicit residual risk rather than being inferred from shared tests.

## Residual Risk

- macOS watchdog runtime, macOS locale/layout, macOS local-media import, and macOS ONNX VAD
  streaming remain unverified on a real macOS host; Windows evidence is recorded.
- Inspiration Profile v2 native packaged launch was not executed in a sandboxed environment; no
  real AI Credit was consumed.
- Transcript Dissection real paid-supplier smoke and native packaged cross-platform UX remain
  unverified; automated worker, frontend, and Rust gates pass.
- Web user sessions carry no IP/UA binding; a stolen cookie is usable for the full 90-day TTL
  (v1 parity with the desktop session).
- Production `secureCookies` on `frameq.8xf.pro` must be verified before announcing the
  dashboard URL; if the reverse proxy terminates TLS while the app sees HTTP, session cookies
  could transit without `Secure`.
- The `lang` cookie is not `Secure` (non-sensitive preference; acceptable for v1).
- Real LLM providers may ignore best-effort output-language instructions; FrameQ does not detect
  or translate mismatched output and does not spend another AI Credit automatically.
- macOS Gatekeeper manual approval remains required until Developer ID signing and notarization
  are adopted.
- External video-platform availability may change; public-link download capability is bounded by
  upstream platform behavior.
- GitHub Releases download speed may be slow in some networks; macOS does not provide in-app
  auto-update.
