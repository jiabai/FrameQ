# FrameQ v0.3.8 Desktop Release

## Intent

Publish the current desktop source as v0.3.8 for the existing personal-development and small-user distribution scope. Two user-visible changes ship: the bundled `yt-dlp` is upgraded from 2026.7.4 to 2026.8.19 so YouTube media-stream fetches stop being rejected with HTTP 403, and Settings > App Updates gains a read-only "current version" line. No local-first, packaging, privacy, or progress-contract boundary changes.

The reason this release exists at all is distribution, not source: users already running v0.3.7 or older carry the frozen `yt-dlp` inside their installed runtime, so a lockfile fix only reaches them through a new installer. `uv.lock` is the sole authoritative source for the bundled runtime's dependencies — `scripts/build-installer.mjs` resolves them at build time via `uv export --no-dev`, and `FRAMEQ_PYTHON_STANDALONE_URL` supplies only a bare CPython archive with no FrameQ dependencies inside it.

## Boundaries

The `yt-dlp` upgrade changes only the media-stream fetch step; audio preparation, ASR, and artifact export are untouched, and no new progress event, contract field, or IPC command is introduced. The version display reuses the existing `get_update_delivery` command and adds one field whose value is the compile-time crate version, so the displayed number cannot drift from the version the updater compares against. Neither change loads ASR libraries, model weights, credentials, private configuration, or local outputs into the release. The desktop release does not deploy or migrate production server data. A first subtitle attempt may still be rate-limited by the platform; the worker's existing drop-subtitles retry is unchanged and remains the recovery path. The platform-side error classification gap (403 and 429 falling into the generic `YOUTUBE_DOWNLOAD_FAILED` bucket, and its misleading "check your network" copy) is deliberately out of scope for this release and stays tracked as debt.

## Acceptance

Desktop versions agree at 0.3.8; local relevant suites and the hosted macOS Cargo tests pass; Windows installer/updater and both macOS DMGs build from the release tag. The upgrade is accepted only with a real end-to-end download against a live YouTube URL on the upgraded runtime, not on a simulated extract. Release notes and the task ledger record validation and native smoke limitations. Published runtime source must match main; any subsequent publication-ledger-only commit is explicitly identified.
