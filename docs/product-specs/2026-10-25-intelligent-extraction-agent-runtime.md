# 智能提炼 agent_runtime 生成规格

## 用户行为与生成边界

- 要点总结、启发灵感、文字稿解剖统一通过 `agent_runtime.ToolLoopAgentRunner` 执行。三个目标各自拥有交付工具、内容校验和完成条件。
- 要点总结顺序交付脑图与总结。启发灵感读取正式文字稿与本次偏好，提交完整灵感列表。文字稿解剖读取带编号的正式文字稿分段，提交完整结构报告。
- 有效工具交付直接结束运行；普通回复不能完成任务。无效交付通过工具反馈说明校验问题，agent 在六次实际调用上限内修改交付。
- 文字稿解剖继续限制最多 16 个分段，每段最多 2000 个 Unicode 字符；确认面板显示 1 至 6 次调用并要求至少 6 个 AI Credits。
- 每次实际托管 LLM 调用独立 checkout，使用从本次任务标识派生的调用标识。失败和修正调用遵循相同计费规则。

## 产物与失败

- 产物路径、JSON schema、输出语言、历史恢复和原子提交契约继续有效。灵感 ID 顺序、主题唯一性、原文分段引用及文字稿解剖的 SHA-256、字节区间和逐字引用继续校验。
- 空稿、越界文字稿和无效语言在调用前拒绝。未交付、超出调用上限、provider 错误或 checkout 失败返回结构化错误；失败时保留已有产物。
- 生产代码删除 `insightflow/` 目录以及旧客户端、固定规划、map-reduce 和单独修补调度。提示词、分段器、产物提交和报告校验分别由 worker 自有模块维护。
- 成稿与文字稿整理继续使用自身已有流程，公共依赖改为新的模块路径。

## 隐私

- 要点总结与文字稿解剖只提供正式文字稿、生成指令及本次工具反馈；启发灵感另外提供确认时的偏好快照。
- 三个目标均无浏览器、搜索、任意文件读取或 skills 工具。FrameQ 服务端仅接收 checkout 数据，原文和生成内容直接发送至管理员配置的 LLM 地址。

## 验收

- 本地执行真实工具处理、报告校验、分段、产物序列化、原子保存、语言与请求契约测试。
- 使用真实 LLM 验证三个 agent 的交付循环、逐次 checkout、完整产物和失败传播；缺少凭证时明确记录未验证范围。
- worker ruff、完整 pytest、前端 lint/测试/build、相关脚本测试和文档校验通过；活动代码与资源检查不再引用旧目录。
