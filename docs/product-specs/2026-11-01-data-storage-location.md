# 数据存储位置与可恢复迁移

状态：已实现，Windows原迁移验收见 `docs/exec-plans/completed/2026-11-01-data-storage-location-plan.md`，预检查进度与取消验收见 `docs/exec-plans/completed/2026-11-02-storage-preflight-progress-plan.md`，已有目录合并验收见 `docs/exec-plans/completed/2026-11-03-storage-directory-merge-plan.md`。有效数据位置由本机受控记录决定；macOS及复制中途磁盘耗尽的环境验证保留未验证。

## 用户目标

在「设置 → 基础」通过一个「数据存储位置」设置项，把主要本机资料迁移到用户选择的数据盘，释放系统盘空间。
迁移包含笔记、合集、模型和运行组件；已有目录合并遵守目标同名文件优先规则。失败或中断时能够继续，用户不需要修改环境文件或手工搬运目录。

## 已确认的入口与布局

- 将现有「输出目录」升级为「数据存储位置」，移除原路径文本输入及其随配置保存的目录写入职责。
- 左侧上方显示标题，下方显示当前有效路径；右侧显示「更改」。沿用现有系统字体、14px 操作、12/13px 路径辅助文字、实色按钮与圆角。
- 路径可单行省略，保留完整原值的辅助技术读取和悬停提示；窄窗口可自然换行，不出现横向溢出。
- 「更改」独立于设置页「保存配置」，通过原生目录选择、预检、明确确认启动迁移。仅选择目录或取消不会改变有效位置。
- 现有「缓存」分类继续提供播放缓存清理；数据位置只有基础页这一处入口，不增加新的存储分类。
- 截图只提供布局参考，遵守 `RULES.md` 的视觉功能限制。实现与实际验收默认使用数值、AX 和真实输入。

## 数据边界

| 内容 | 迁移后归属 |
| --- | --- |
| 任务自有视频、音频、文字稿、网页正文、总结、脑图、灵感、解剖与草稿 | 数据根下 `outputs/tasks/<task_id>/`，盘点整个任务目录，合并时目标同名文件优先 |
| 自动标题、固定、手动名称、原稿备份、sidecar、任务事务材料 | 随所属任务目录迁移，保持 task ID 和相对路径 |
| 合集及成员关系 | 数据根下 `collections.json`，保持合集 ID 与 taskIds |
| ASR 模型、版本标记、模型下载材料 | 数据根下 `models/`，按原布局迁移 |
| 按需下载的运行组件及版本/指纹文件 | 数据根下 `runtime/`，按原布局迁移 |
| 处理缓存、下载中间材料、播放缓存 | 数据根下 `cache/`，保留任务对应关系 |
| 迁移库存、校验与清理凭据 | 数据根的应用自有元数据区域；固定目录只保留有界控制记录和引用 |
| 登录凭据、应用设置、语言/更新/灵感偏好、应用日志、位置控制记录 | 继续保留在系统默认应用目录 |
| 安装包中的 Python、worker、媒体工具及程序资源 | 保持安装位置 |
| 用户导入过的外部原始媒体、共享目录中的无关文件 | 保持原位置，不纳入清理 |

用户选择例如 `D:\FrameQData` 后，主要数据采用该根；默认应用目录仍保留凭据、设置、日志和少量位置/恢复配置。
任务缓存内部的历史诊断材料随所属缓存按字节保留；应用级 `logs/` 始终保留在固定目录。

## 当前用户与旧输出目录兼容

- 升级后不自动搬迁已有资料。首次兼容解析遵守当前有效输出根优先级：本机 `.env` 非空设置、进程环境设置、默认 `outputs/`。
- 已退役网页组件继续按原文件纳入库存、哈希和复制校验；旧 schema1 baseline 的可选 `readyWebEngine` 字段仍可读取，不执行其浏览器启动探针。系统 WebView 宿主随应用安装资源交付，已有笔记读取不依赖该宿主。
- 迁移前同时检查有效旧输出根与默认 `outputs/` 中的遗留资料，以及现有模型、组件、缓存、合集。
  确认页显示实际来源，不能用当前可见历史名单代替完整库存。
- 任务目录中的旧版、未识别或损坏资料按原件保留，迁移不会使其成为受信任或可执行的当前任务。
  已确认属于应用的任务树按字节迁移；自定义输出根中归属不明的旧文件必须列出并阻止含糊的切换，不能静默遗漏、覆盖或猜测归属。
- 两个来源指向相同目录时只盘点一次。相同 task ID 的整树内容完全一致时保留一个目标副本并记录两个来源；内容不同则阻止迁移并明确列出冲突。
- 旧输出值为相对路径时，分别核查Rust启动工作目录与固定配置目录两种旧解释。不能唯一确定来源时进入兼容确认，要求定位并核对原资料；不自行选择一个基准或扫描整盘猜测资料位置。
- 自定义输出根可能是共享目录，只处理确定属于 FrameQ 的子树，不复制凭据或清理整个共享目录。
- 成功采用统一数据根后，受控位置记录成为桌面的路径权威；旧输出键继续作为兼容来源记录保留，不再通过普通设置保存或进程环境改变新库。
  独立 worker 的既有目录环境变量能力保持不变。

## 用户流程

- 迁移预检查明确区分等待已有操作、盘点文件、校验现有资料、完整性校验和检查目标目录。盘点时显示实际发现数量；总数未知时不显示0/0或虚构百分比。完整性校验显示已核对文件及真实读取字节，大文件显示当前读取量。
- 从点击旧位置清理入口开始，弹窗标题始终为「清理旧位置」。预检查显示「正在核对旧副本」、已核对文件数/总数及当前大文件读取进度；完成后展示可删除文件数量、大小和需保留数量，明确确认后才删除。
- 预检查取消必须使实际后台盘点/哈希/验证停止，等待后台收尾后解除操作冻结。已取消会话的进度或迟到结果不得重新打开确认界面或签发有效删除许可。
- 预检查进度为当前请求的临时状态，绑定窗口、请求ID和资料库代次，不改变复制、位置提交、恢复或删除的持久阶段语义；删除前继续重新核对两端身份与完整散列。

下列复制、核对及后续确认清理步骤用于空目标。已有资料的目标在预检查和现有确认入口之后执行合并：目标同名文件保留并删除源文件，缺少文件移动，完成后清理源空目录、提交位置并重启验证。合并开始后暂停取消与普通资料操作，失败时继续原合并。

1. 点击「更改」并选择本机目录。校验目录关系、文件系统能力、写入权限、可用空间与已有内容。
2. 界面先冻结新的数据动作，等待已经开始的处理、下载、生成、保存和后续合集提交完整结束。
   对未保存文字稿、草稿、名称/合集表单、设置或档案草稿，使用所属编辑会话的保存、放弃、取消保护，不自动丢弃。
   上述跨IPC收尾完成后，再由Rust停止新的数据许可并取得独占；等待期间已有保存/成员提交能够正常完成。
3. 在静止的资料集上生成最终库存。确认页显示来源、目标、范围、文件/字节数量、所需空间、重启要求和原件保留方式；明确确认后才复制。
4. 显示「复制」「核对完整性」「保存位置」的真实文件/字节进度。切换前可以取消；取消保持原位置有效，已产生的副本和恢复记录可继续核查。
5. 逐文件校验成功后，原子保存新位置。提交过程不可取消，随后显示「需要重启」，数据操作继续暂停，避免同时使用两个位置。
6. 重启后验证新位置的任务、合集、模型、运行组件和缓存读取。模型/组件与迁移前就绪状态比较，原本缺失或过期的内容保持原状态；成功后恢复正常操作，并提供明确确认的「清理旧位置」。
7. 清理仅删除已迁移、两端仍有一致副本且身份校验通过的应用文件。新旧内容发生差异的文件继续保留并说明；只移除已清空的应用自有子目录。
   默认配置根、共享输出根、外部原文件及未纳入库存的文件不递归删除。

## 校验、互斥与恢复

- 目标接受空目录、已有资料目录及当前迁移的中断恢复目录。空目录沿用复制、核对、切换和确认清理流程。
- 已有资料目录采用用户确认的合并规则：按相对路径和文件名判定重复，目标已有文件时保留目标并删除源文件，即使内容不同；目标缺少文件时移动源文件。重复判定不比较内容，不生成冲突版本、备份或重复项提示。目标独有文件保持原位，`collections.json` 同样遵守目标优先规则。
- 合并预检查不修改源资料；现有迁移确认入口显示合并规则，确认后执行。开始移动或删除后不能取消；失败或强制退出保持恢复记录和数据操作暂停，继续完成同一个合并，避免应用读取已移动一部分的源目录。
- 合并逐文件保存操作记录，同卷通过无覆盖重命名移动，跨卷完成复制校验后删除源文件。重复项只核对两端类型与身份，不要求内容相同。文件与目录的类型冲突、不安全链接和目录身份变化会中止操作并保留恢复入口。
- 合并完成后清理已经清空的源应用目录，保留固定配置目录、外部共享根及无关文件。目标资料库标记与位置记录统一更新，重启从目标扫描任务和读取合集，路径从新的有效目录重新生成。
- 拒绝目标等于来源、任何来源的祖先/后代、安装资源目录、链接/reparse 绕行、路径别名导致的嵌套和文件与目录的类型冲突。
  正规目录与文件身份必须在关键步骤重新核对，不能只做字符串前缀判断。同路径的常规文件适用目标优先合并；文件与目录的类型冲突阻止操作。
- 空间预检使用当前用户实际可用空间，包含文件逻辑大小、文件系统分配/元数据余量、临时材料和固定配置盘的提交空间；复制过程继续处理真实空间耗尽。
- 后端统一访问许可覆盖任务、两个 worker 执行通道、下载、生成、保存、笔记/合集、删除、缓存清理，以及历史扫描事务恢复、播放缓存创建等隐含写入。
  前端禁用状态用于解释，不能作为唯一互斥。
- 不修改任务内的相对路径、Markdown 正文或用户外部来源；重启后通过新的已验证根重新生成绝对路径。
- 播放授权只开放已验证输出与播放缓存的必要子树，不授权整盘或凭据目录。
- 迁移记录持久保存阶段、两端身份、库存摘要及提交状态；复制/校验前后、位置提交前后、重启验证与清理中断均能重新判定权威位置。
- 空目标复制在保存位置前失败或取消：旧位置保持权威，显示继续/取消迁移的明确入口。新副本不自动成为有效资料库。已有目录的合并开始后保持资料暂停，必须继续完成，不能恢复对部分源目录的普通写入。
- 取消会解除当前迁移的操作门禁，恢复旧位置使用，并保留带身份/摘要的部分副本记录；再次继续必须重新核对来源。失败保留实际持久阶段及独立错误信息，不能用错误标签丢失提交边界。
- 保存位置后中断：重启依据已经提交的位置继续验证；不自动退回旧副本，不启动旧目录的新写入。
- 目标磁盘离线、记录损坏或目录身份不匹配：进入独立恢复界面，提供重新检测、重新定位并校验现有资料等入口；不创建默认空库，不把错误显示成零条笔记。
- 重新定位须匹配当前库的物理目录身份及library/generation，支持同一目录盘符变化；较早克隆不能只凭标记成为当前库。
- 首次重启验证通过后，正常编辑继续有效；以后启动不再用迁移时的旧散列否定合法编辑。仅有待清理凭据不阻止使用资料库。
- 多次迁移后，旧位置清理始终核对当前有效位置的相对文件；不能用另一个旧副本证明可以删除原件。
- 所有常规关闭、应用更新安装/重启与迁移阶段协调；强制退出依赖持久记录恢复，不假称已完成。
- 迁移不访问网络、不上传路径或资料、不启动模型下载、ASR 或付费生成；现有凭据、权限、原子文件与任务事务边界继续有效。

## 验收标准

- 使用真实文件、完整 SHA-256、正式生产服务函数与独立进程验证同盘/跨盘迁移和重启；不使用假的文件系统、IPC、进度或模型就绪标记。
- 覆盖默认目录、实际旧环境优先级、默认遗留资料、同 ID 冲突、旧版/损坏目录、未完成任务事务及删除恢复。
- 验证真实权限拒绝、空间不足/复制耗尽、路径冲突、源/目标替换、链接与 hardlink、取消和每个持久阶段的进程终止。
- 后端真实并发读写与两个 worker 通道证明迁移期间没有新的数据写入；dirty/busy/更新/关闭分支通过对应前端回归。
- 重启后的任务、合集、播放、模型校验和运行组件导入需分别有证据；有真实模型/组件时运行本地短语音读取/ASR，复制占位文件不能作为模型功能验收。
- 三语覆盖设置行、确认、进度、取消、失败、离线恢复、重启及旧位置清理；覆盖已采用的四CSS视口、键盘、焦点和实际滚动。
- 测试资料位于隔离的 ignored 工作目录；不自动迁移、清理当前用户的实际库。需要真实容量受限卷或其他平台而环境未具备时，明确记录未验证，不能用返回假错误替代。
- Rust、前端、worker相关回归、脚本、文档与Windows构建按执行计划完成；实际通过范围、原生检查与环境限制记录在已完成执行计划中。
