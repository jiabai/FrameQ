# FrameQ v0.3.0 Desktop Feature Release Spec

## Status

Proposed on 2026-08-03 for release preparation. Tag creation, hosted Draft
publication, and broad consumer publication remain separate approval checkpoints
after the release-prep diff is reviewed. All v0.2.17 broad-release reliability
blockers (atomic persistence, worker watchdog, server auth/quota concurrency,
server production operations) remain accepted; v0.3.0 inherits them without
re-running their dedicated failure-injection evidence.

## Release Intent

FrameQ v0.3.0 is a stable minor desktop release for the existing
personal-development, small-user, and open-source distribution model. It packages
the completed local-media import, selectable SenseVoiceSmall-ONNX with on-demand
download, streaming ONNX VAD with fail-closed contracts, transcript dissection AI
target, and the bundled ONNX runtime integrity work as one compatible
desktop/worker release. The release keeps the local-first runtime, lightweight
installer, entitlement, SourceIdentity, and disabled-WeChat-payment boundaries.
The minor bump reflects user-visible new capabilities and ASR failure-semantics
changes; the distribution, billing, and trust model are unchanged.

## Included Scope

- Single-file local video/audio import through a Rust-owned native picker with
  opaque selection tokens, normalized 16 kHz mono 16-bit PCM WAV, source-aware
  artifacts and History v3 variant, and strict path secrecy (Windows native
  acceptance recorded; macOS runtime remains residual risk).
- Selectable local ASR model: default PyTorch SenseVoiceSmall preserved, optional
  ModelScope-only `funasr_onnx` runtime and selected-model on-demand download
  before task submission, with no startup auto-download and no task created on
  cancellation/failure.
- Streaming ONNX VAD through bundled `Fsmn_vad_online` with stateful endpoint
  events, one `ndarray` per SenseVoiceSmall-ONNX call, terminal failure on any
  VAD/audio/block preparation error, and removal of all whole-audio VAD/ASR
  paths.
- Bundled ONNX runtime dependency integrity: packaged worker ships the required
  ONNX runtime wheels, and a repository test guards the bundled set.
- Transcript Dissection (`文字稿解剖`) AI target: independent confirmed target on
  saved transcripts, bounded per-call quota, deterministic UTF-8 source
  provenance, managed per-call checkout, strict structured generation, atomic
  `ai/dissection.json` + `ai/dissection.md`, Rust-validated History restoration,
  and three-locale UX.
- Tauri IPC runtime-decoding boundary: Account, History, settings, transcript
  detail, and FrameQ-owned update command runners return `Promise<unknown>`; each
  domain decodes closed top-level/nested DTOs before state mutation.
- Closed worker terminal-result contracts across Python, Rust, and TypeScript
  (operation-specific closed result families, exactly one terminal stdout JSON
  line, no echoing of rejected payloads).
- Python worker application facade / CLI boundary, Rust worker runner module
  split, frontend transcript controller split, Server Store/PrismaStore split,
  and ASR model-download capability boundary refactor (governance-only; no
  user-visible behavior change).
- Estimated text-position seeking in transcript playback.

## Excluded Scope

- No new language, no automatic AI-output detection, translation, retry, or
  provider call beyond the existing `retry_insights` and `文字稿解剖` targets.
- No ASR model weight, LLM credential, payment credential, user configuration,
  log, task, or user artifact is added to an installer; the installer remains
  lightweight and the core ASR model is downloaded only when a verified task is
  submitted and the selected model is missing.
- No Linux artifact, no Universal macOS binary, no App Store review, no Apple
  notarization, no Developer ID signing.
- No WeChat payment enablement; `WECHAT_PAY_ENABLED` stays default off.
- Inspiration-to-draft generation and the standalone marketing site remain
  design/documentation work.

## Supported Artifacts

- Windows x64 NSIS installer, updater signature, and `latest.json`.
- macOS Intel (`x86_64`) DMG.
- macOS Apple Silicon (`aarch64`) DMG.
- No Linux artifact or Universal macOS binary.

## macOS Trust Boundary

The v0.2.16 ad-hoc-signing policy remains unchanged. Both macOS app bundles must
pass bundled-runtime, Deno, and `codesign --verify --deep --strict` checks on
GitHub-hosted macOS runners, but they are not Developer ID signed or notarized.
Release notes must place the Gatekeeper disclosure before download links and must
not imply App Store review, notarization, or silent enterprise deployment.

## Release Flow

1. Synchronize all five desktop version sources at `0.3.0` and keep the automated
   drift test (`scripts/check-release-version.mjs` and
   `scripts/tests/release-version.test.mjs`) GREEN at the new version.
2. Run the complete local release gates on the release-prep diff and record exact
   evidence (script tests, app tests/lint/build, Rust tests/rustfmt, worker
   tests/Ruff, server tests/build, governance validation, diff checks, refreshed
   packaged-worker SHA-256 equality, and Tauri `--no-bundle`).
3. Do not create a tag, run Desktop Release, or publish a GitHub Release until the
   release-prep diff is reviewed and approved.
4. Commit and push the verified release changes only after review, then create
   annotated tag `v0.3.0` as a separate action.
5. Let the tag-triggered Desktop Release workflow create a Draft Release and build
   all three platform artifacts from one tagged commit.
6. Inspect artifact names, updater metadata, bundled runtime imports, Deno smoke,
   macOS codesign output, and release notes before publishing the Draft as a
   stable non-prerelease release.

## Acceptance Criteria

- `app/package.json`, `app/package-lock.json`, `app/src-tauri/Cargo.toml`,
  `app/src-tauri/Cargo.lock`, and `app/src-tauri/tauri.conf.json` agree on
  `0.3.0`.
- `scripts/tests/release-version.test.mjs` asserts `0.3.0` and the explicit
  version checker reports consistent sources.
- App tests, lint, production build, Rust tests/rustfmt, worker tests/Ruff,
  server tests/build, script tests, documentation validation, and diff checks
  pass.
- A Tauri no-bundle release build succeeds with a freshly synchronized packaged
  worker.
- The Draft Release jobs succeed for Windows x64, macOS Intel, and macOS Apple
  Silicon, and every uploaded artifact reports version `0.3.0`.
- macOS release acceptance records native locale/layout, local-media import, and
  ONNX VAD streaming status truthfully; unavailable manual evidence remains an
  explicit residual risk rather than being inferred from shared tests.

## Residual Risk

- macOS watchdog runtime, macOS locale/layout, macOS local-media import, and
  macOS ONNX VAD streaming remain unverified on a real macOS host; Windows
  evidence is recorded for the corresponding gates.
- Transcript Dissection real paid-supplier smoke and native packaged
  cross-platform UX remain unverified; automated worker, frontend, and Rust gates
  pass.
- Real LLM providers may ignore best-effort output-language instructions; FrameQ
  does not detect or translate mismatched output and does not spend another AI
  Credit automatically.
- macOS Gatekeeper manual approval remains required until Developer ID signing
  and notarization are adopted.
- External video-platform availability may change; public-link download
  capability is bounded by upstream platform behavior.
- GitHub Releases download speed may be slow in some networks; macOS does not
  provide in-app auto-update.
