# FrameQ v0.3.0

FrameQ v0.3.0 是面向个人开发、少量用户和开源工具场景的稳定桌面版本，支持 Windows
x64、macOS Intel 和 macOS Apple Silicon。本版本新增本地媒体文件导入、可选
SenseVoiceSmall-ONNX 模型按需下载、流式 ONNX VAD 与 fail-closed 转写契约、文字稿解剖
AI 目标，以及内置 ONNX 运行时完整性。视频、音频和文字稿仍默认在本机处理与保存，核心
ASR 模型仅在用户提交已验证任务且所选模型缺失时下载。

## macOS 首次打开（下载前请阅读）

macOS DMG 使用 **ad-hoc 签名，未经过 Apple notarization（公证）**。这能验证应用包在
构建后未被修改，但不能建立 Apple Developer ID 身份。因此从 GitHub 下载后，macOS 会在
第一次启动时阻止直接打开。

当前 macOS 的推荐打开方式：

1. 将 FrameQ 拖入“应用程序”并尝试打开一次，然后关闭系统警告。
2. 打开 **系统设置 → 隐私与安全性**。
3. 找到 FrameQ 的拦截提示，点击 **仍要打开（Open Anyway）** 并再次确认。

macOS 14 及更早版本也可在“应用程序”中按住 Control 点击 FrameQ，选择“打开”。如果图形
界面入口不可用，可使用以下终端命令作为后备方式：

```bash
xattr -dr com.apple.quarantine /Applications/FrameQ.app
```

FrameQ 当前不宣称已通过 Apple 公证、App Store 审核或适合静默企业部署。macOS 更新采用
手动下载安装新版 DMG；Windows 继续使用现有签名 updater 元数据。

## 主要改进

### 本地媒体文件导入

新增单文件本地视频/音频导入路径。通过 Rust 原生选择器拾取 MP4/M4V/MOV/MKV/AVI/WMV/WebM
视频或 MP3/WAV/M4A/AAC/FLAC/OGG/Opus/WMA 音频，使用不透明选择 token，把所有源完整路径
挡在 React、持久化、日志和云端之外。视频容器保留原样，音频源统一归一化为 16 kHz 单声道
16-bit PCM WAV；严格 schema-v3 History 新增 closed local-source 变体，转写任务不会因为本
地源泄漏路径。

### 可选 SenseVoiceSmall-ONNX 与按需下载

默认 PyTorch SenseVoiceSmall 模型保留不变，新增可选 `funasr_onnx` 运行时。用户在提交已
验证 URL 或本地媒体任务时按所选模型按需下载到 app-local data；启动时不会自动下载模型，
取消或失败不会创建任务，并自动恢复原 URL/本地媒体意图。安装包不内置 ASR 权重、LLM key、
云端 LLM 模型或用户私有配置。

### 流式 ONNX VAD 与 fail-closed 转写契约

VAD 改为通过内置 `Fsmn_vad_online` 流式处理有界分块，收集其有状态端点事件；每次
SenseVoiceSmall-ONNX 调用仅接受一个 `ndarray`。任何 VAD、音频或分块准备失败即为终态
失败，不再回退到整段音频 VAD/ASR 路径。95 分钟验收样本：571 次 VAD 调用、808 次仅
ndarray ASR 调用、808 段文字稿、21,774 字符、202.015 秒耗时。

### 文字稿解剖（`文字稿解剖`）

智能提炼工作区新增第四张 target 卡片，对已保存文字稿做结构化拆解。每次调用独立确认、
有界额度、确定性 UTF-8 源出处、托管 per-call checkout、严格结构化生成；产物原子写入
`ai/dissection.json` + `ai/dissection.md`，Rust 端验证 History 恢复，失败重跑保留既有报
告，三语言 UX。

### 内置 ONNX 运行时完整性

打包 worker 内置所需 ONNX 运行时 wheels，仓库测试守护内置依赖集合，避免在干净机器上
因缺少 ONNX 运行时而无法启动 ONNX 路径。

### Tauri IPC 运行时解码边界

Account、History、剩余设置、文字稿详情和 FrameQ 自有更新命令 runner 统一返回
`Promise<unknown>`；每个域在状态变更前解码封闭的顶层/嵌套 DTO。畸形、accessor、symbol
或异类值通过稳定的非回显 `IpcProtocolError` 代码失败，worker/local-media 专用解析器与有
效行为保持不变。

### 转写播放估位 seek

文字稿播放新增基于文本位置的估算 seek，便于在长文字稿中快速定位段落。

### 治理性模块拆分（无用户可见行为变更）

Python worker application facade/CLI 边界、Rust worker runner、Server Store/PrismaStore、
前端 Transcript controller、ASR 模型下载能力边界、视频处理 task-result adapter、worker
终端结果闭集、媒体准备 facade、worker 原子产物提交、task access facade、视频处理/ASR/
Transcript detail/Bilibili/Xiaohongshu/Douyin fallback 模块拆分均已完成，仅是结构性治
理，不改变产品、隐私、契约或打包行为。

## 隐私与安全

- 本地媒体导入使用不透明选择 token；源完整路径不进入 React、持久化、日志、History
  manifest 或云端 AI 请求。
- 文字稿解剖仅接收已保存文字稿和固定结构化生成约束；界面语言切换不会改变 ASR、字幕选
  择、原始文字稿、缓存或既有历史产物。
- ONNX VAD 流式路径不会回退到整段音频推理；任何分块失败即为终态失败，不再尝试整段重试。
- 安装包不包含 ASR 模型权重、LLM key、支付凭据、用户配置、日志、历史任务或用户产物。
- 微信支付仍未启用，`WECHAT_PAY_ENABLED` 继续默认关闭；当前授权方式仍是管理员发放的
  激活码。
- v0.2.17 接受的原子持久化、worker watchdog、server 鉴权/额度并发和 server 生产运维加
  固继续生效，本版本不重新触发各自的失败注入证据。

## 已知限制

- macOS：watchdog 运行时、locale/layout 物理验收、本地媒体导入和 ONNX VAD 流式已于
  2026-08-06 在真实 macOS 主机完成实测验收；Windows 对应验收证据此前已记录。GitHub
  runner 的构建、运行时导入和签名完整性检查不能替代真实窗口体验。
- 文字稿解剖：原生打包跨平台 UX 未实测；真实付费供应商 smoke 已于 2026-08-23 用
  SiliconFlow + deepseek-ai/DeepSeek-V3.2 完成端到端烟测闭合（完整链路 map→reduce→repair
  266.8s 通过，含 highlight 逐字引用修复）。自动化 worker、前端和 Rust 门禁通过。
- AI 输出语言是 prompt 约束，供应商仍可能返回其他语言。FrameQ 不会自动检测、翻译或重试，
  也不会因此自动消耗额外 AI Credits。
- macOS 首次启动需要上述 Gatekeeper 手动授权，直到未来采用 Developer ID 签名与 Apple
  notarization。
- GitHub Releases 在部分网络环境中的下载速度可能较慢；macOS 不提供应用内自动更新。
- 外部视频平台页面或接口可能变化，公开链接下载能力仍受平台可用性影响。
