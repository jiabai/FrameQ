# FrameQ v0.3.2

FrameQ v0.3.2 是基于 v0.3.1 的桌面补丁版本，加入用户主动导出本地诊断 ZIP 的能力，帮助
用户在遇到 ASR 模型下载或桌面运行问题时把必要的安全诊断信息交给维护者。媒体、文字稿、
模型权重、LLM key、用户配置和私有产物仍不会进入安装包或诊断导出。

## 下载选择

- Windows x64：`FrameQ_0.3.2_x64-setup.exe`
- Intel Mac：`FrameQ_0.3.2_x64.dmg`
- Apple Silicon Mac（M 系列）：`FrameQ_0.3.2_aarch64.dmg`

macOS 仍使用 v0.3.1 的 ad-hoc 签名与 Gatekeeper 首次打开流程；本版本不宣称 Apple
notarization 或 App Store 审核。

## 主要改进

### 桌面诊断导出

- 设置 → 高级提供“导出诊断”入口；ASR 模型下载终态失败时，失败界面也提供同一入口。
- 导出使用原生 Save As，由用户选择目标位置；取消、忙碌、目标不可写和重复点击均闭合处理。
- ZIP 只包含固定根目录条目，诊断内容由 Rust 在导出时再次脱敏、截断和去重；导出本身不
  上传、不发起 DNS/HTTP 请求、不调用服务器、LLM 或模型下载。
- 诊断日志默认保留最近七天并受大小、行数和单条字符上限约束；ASR 下载 stderr 仅作为
  受限兜底信息保存。

### Worker contract v8

新增结构化 ASR 模型下载诊断事件通道。诊断事件不刷新 watchdog，不改变 stdout 终态结果，
非法或不受信任内容只留下固定拒绝标记。

## 隐私边界

诊断导出不会包含媒体、文字稿、模型文件、`.env`、账户信息、路径、主机/IP、URL、代理、
token、任务 ID、原始异常或 traceback。FrameQ 不会自动上传诊断包，用户需手动将 ZIP 交给
维护者。

## 验收记录

- 合并后的 Windows Rust 串行测试命令为：
  `cargo test --manifest-path app\\src-tauri\\Cargo.toml -- --test-threads=1`。
- 原生 Save As 手动验证已完成。
- 本地 Windows 上既有 watchdog 子进程 fixture 可能因 `taskkill` 权限/并发环境返回
  `Access denied`；该环境残余不代表诊断导出失败，合并后的 hosted CI 与三平台 Desktop
  Release 构建是发布门禁依据。

## 已知限制

- macOS 首次打开仍需按 Gatekeeper 提示手动授权。
- 诊断导出不会自动附加到工单或上传服务；用户需要手动发送 ZIP。
