# FrameQ v0.5.0

## 主要变化

- **全新的桌面工作区**：主页、侧栏和笔记列表重新排布，任务、笔记、合集与本地数据在同一处管理。分栏宽度可以拖动并会记住比例，弹窗与主界面使用同一套样式。笔记支持置顶、改名、查看来源与信息、加入合集，以及确认后永久删除。

- **处理过程有完整画面**：提交链接后，中间区域显示当前动作、真实进度和阶段。视频链接依次经过准备媒体、转写和生成标题；网页链接依次经过加载网页、提取正文和保存笔记。取消、失败重试与修改输入的入口保持明确，失败后重试会核对仍是同一个来源。进入已保存的文字稿后，阅读区继续保持可用。

- **网页链接也能保存成笔记**：在主页输入框粘贴公开或已授权的网页地址，FrameQ 会加载页面、提取正文并保存为本地笔记。网页提取使用系统自带的网页组件，无需额外下载浏览器。每次保存包含标题、规范后的来源网址、提取时间和正文；每次提交都是独立快照，不会覆盖已有笔记及其改名与合集归属。阅读本地笔记时不执行网页脚本，也不会自动加载外部图片或字体。网页笔记沿用现有的总结、脑图、灵感和确认后扣费规则，加载与保存本身不调用云端模型。

- **数据存储位置可以自己选，并且能安全迁移**：设置里的「输出目录」升级为「数据存储位置」。迁移前先盘点、复制、逐文件核对，再原子切换；进度按阶段显示，可以在后台取消。目标目录已有内容时按同名规则合并，同名文件以目标为准，空目录会被清理。凭据、设置和日志仍留在系统默认应用目录。

- **文字稿结果页更清爽**：去掉与「定位文字稿」重复的「导出」按钮；底部复制按钮改名为「复制当前内容」，避免与工具栏的「复制文字稿」混淆。

- **macOS 上网页提取与存储更稳**：原生网页组件改为逐条读取命令，不再等待输入关闭；存储管理器在退出时主动释放自己持有的文件锁，避免旧进程残留的重复句柄挡住新实例。

- **安装包里的运行环境更精简**：默认语音识别使用轻量 ONNX 运行时，安装包不再附带 PyTorch 权重；需要 PyTorch 版模型时仍可按需下载组件。

## 边界与验证

安装包不含语音识别权重、密钥或用户私有配置。本地优先边界不变：视频、音频、文字稿、模型缓存与本地历史仍全部留在本机。网页提取只处理公开或已授权的网页，不导入浏览器登录状态，不处理验证码，不绕过访问限制；来源网址经规范化后才写入笔记，日志与错误不含原始请求网址。

验证情况：前端 1503 项通过（1 项跳过），Rust 557 项通过（29 项忽略），转写服务本地 1265 项通过（4 项跳过）、托管双平台各 1269 项全部通过；服务端 400 项测试、八条迁移、预检与隔离恢复通过；脚本测试 57 项与 Python 脚本 1 项通过，文档校验 ERROR 与 WARN 均为 0。Windows 正式安装包覆盖安装后，53 个原有任务文件的 SHA-256 全部保持不变；安装版默认模型对 86 分钟音频完成识别，产出 80,951 字符与 300 个有序片段，结果与原生运行一致。macOS Intel 与 Apple Silicon 内部制品各通过 534 项原生测试，并完成真实网页保存、重开、应用与运行环境检查及 DMG 回读。

## 已知局限

- macOS 图形界面交互、首次打开时的权限与 Gatekeeper 交互，以及部分网页组件专项安全检查尚未在真机完成。
- macOS 安装包使用临时签名，未经过 Apple 公证，首次打开仍需手动放行。
- 内部验收安装包关闭了自动更新的签名校验文件，公开的签名更新链路未做端到端实测；macOS Intel 验收任务需要手动触发，不随版本标签自动运行。
- YouTube 与 B 站走 `yt-dlp` 的下载仍没有外部超时包装，网络长时间无响应时主要依赖 45 分钟空闲看门狗兜底。
- 使用 PyTorch 版语音模型的用户升级后需要重新下载一次运行时组件（约 140 MB）：组件目录与下载 URL 跟随应用版本号，v0.4.3 的组件不会被复用。默认 ONNX 模型不受影响。
- 2026-11-05 首版 v0.5.0 的用户需要手动重装才能拿到本次修正，自动更新不会为相同版本号推送。
