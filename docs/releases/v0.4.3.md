# FrameQ v0.4.3

## 主要变化

- **新增「整理文字稿」**：结果页文字稿工具栏在还没有整理稿时显示「整理文字稿」。点击后由云端模型做一次适度整理：修正识别错的错字、漏字、断句与标点，删掉不影响原意的口头语和无意义重复，并按语义重新分段。整理稿单独保存为 `transcript/polished.txt`，原始文字稿一个字节都不动。整理成功后按钮变成「复制文字稿」，复制到的就是整理后的正文；重启应用或从历史里恢复同一个任务，这个状态依然成立。整理只提升可读性，不改原意、不增删事实内容、不把原话换成书面语。未登录或账号额度不足时先打开账号面板，不会发起整理。原稿被编辑保存后，整理稿自动视为过期，按钮回到「整理文字稿」。

- **任务不再悄悄从历史里消失**：桌面端与转写服务对「产物该落到哪个目录」的理解此前存在偏差。它只在处理中途异常中断、留下待恢复记录时才会暴露：恢复失败的任务被静默跳过，历史列表里再也找不到它，界面也没有任何提示。现在两侧按同一份清单校验，恢复失败不再等于任务消失。

- **文字稿校对体验**：打开文字稿时第一段不再默认高亮选中；重新打开草稿时会重新读取磁盘上的内容，界面不再停在旧版本。

- **错误提示更准**：云端模型配置异常现在归入智能提炼的错误提示，不再显示为转写阶段的问题；界面提示文案改由受控清单发放，避免显示无法解释的内部代号。

- **编辑原稿后按钮立即回到「整理文字稿」**：此前保存正式稿后工具栏仍停在「复制文字稿」，要重开任务才切换，这段时间里点复制拿到的是改动前的整理稿。现在保存完成即在原处重新判定，按钮立刻回到「整理文字稿」。

- **短视频分享链接解析**：清理表单里的平台短链输入规则，去掉已失效的 X 链接入口，并对提取结果的输出长度设了上限。

## 边界与验证

安装包不含语音识别权重、密钥或用户私有配置。本地优先边界不变：视频、音频、文字稿、模型缓存与本地历史仍全部留在本机。整理文字稿只把文字稿正文送云端处理，不上传视频、音频或本地历史。

验证情况：转写服务全量 1162 项测试通过（3 项跳过）；Rust 354 项测试通过，含看门狗与任务恢复全部用例；前端 86 个文件 867 项测试通过，类型检查、文案检查与生产构建通过；服务端 401 项测试通过（1 项跳过）与构建通过；脚本测试 52 项通过；文档校验 ERROR 与 WARN 均为 0；Python 静态检查通过。「整理文字稿」的整理、复制与重启恢复已在真实安装包实测通过。

## 已知局限

- 本版追加的「保存后立即回到「整理文字稿」」修复尚未在新安装包里复验。
- 诊断信息导出的 macOS 原生保存弹窗仍未取得真机证据（Windows 已完成）。
- YouTube 与 B 站走 `yt-dlp` 的下载仍没有外部超时包装：网络长时间挂住时只有 45 分钟空闲看门狗兜底。抖音降级通道已在上一版修好。
- Apple 芯片与 Intel Mac 的安装包未做代码签名与公证，首次打开仍需手动放行。
