# FrameQ v0.3.3

FrameQ v0.3.3 是基于 v0.3.2 的桌面版本，重点解决「干净 Windows 机器上 ASR 模型下载失败」
的一类根因，并强化下载链路的稳定性与可诊断性。媒体、文字稿、模型权重、LLM key、用户
配置和私有产物仍不会进入安装包。

## 下载选择

- Windows x64：`FrameQ_0.3.3_x64-setup.exe`
- Intel Mac：`FrameQ_0.3.3_x64.dmg`
- Apple Silicon Mac（M 系列）：`FrameQ_0.3.3_aarch64.dmg`

macOS 仍使用 ad-hoc 签名与 Gatekeeper 首次打开流程；本版本不宣称 Apple notarization 或
App Store 审核。

## 主要改进

### Windows 运行库自检

- 安装包在 Windows 上随附 VC++ 2015-2022 运行库（msvcp140 / vcruntime140_1），干净系统
  无需单独安装 Microsoft Visual C++ Redistributable。
- 桌面端在启动任何本地处理前检查运行组件；缺失时给出明确指引（安装运行库或检查安全
  软件拦截后重新安装），不再显示笼统的「模型下载失败」。

### 下载与运行稳定性加固

- 中断的 ONNX 模型下载残留目录会自动清理，不再累积占用磁盘。
- 自定义模型下载源改为带超时、大小上限和自动重试的流式下载，并有真实进度。
- 下载前检查磁盘空间，空间不足时立即提示，不再白等一次大下载。
- 模型缓存校验加强：损坏或截断的模型文件会被识别并重新下载。
- 桌面日志增加大小上限自动滚动。
- 高频下载进度事件节流，降低界面开销。

### 可诊断性

- worker 启动阶段（模块导入期）的崩溃现在会记录一条结构化诊断事件；配合「导出诊断
  信息」可以远程区分运行库缺失、文件被安全软件隔离等问题，无需在用户机器上手动复现。

## 隐私边界

与 v0.3.2 一致：诊断导出不包含媒体、文字稿、模型文件、`.env`、账户信息、路径、主机/IP、
URL、代理、token、任务 ID、原始异常或 traceback；FrameQ 不会自动上传诊断包。

## 验收记录

- Windows 打包产物断言随包三个运行库 DLL 存在；canonical 与打包 worker 字节一致性检查
  已加入发布 CI（`scripts/verify-packaged-worker.mjs`）。
- 干净 Windows（无 VC++ 运行库）烟测结果见发布计划验收记录。
- 本地 Windows 上既有 watchdog 子进程 fixture 可能因 `taskkill` 权限/并发环境返回
  `Access denied`；该环境残余不代表本版本功能失败，hosted CI 与三平台 Desktop Release
  构建是发布门禁依据。

## 已知限制

- macOS 首次打开仍需按 Gatekeeper 提示手动授权。
- 若安全软件隔离了安装文件，仍需用户在安全软件中恢复或重装；诊断导出可帮助确认该场景。
