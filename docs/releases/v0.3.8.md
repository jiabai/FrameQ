# FrameQ v0.3.8

## 主要变化

- **修复部分 YouTube 视频下载失败**：这些视频解析能成功，但取媒体流时被平台拒绝，任务最终失败并提示「请检查网络后重试」——这个提示会把你引向网络，而网络其实是好的。根因是随安装包一起分发的下载组件（yt-dlp）版本偏旧，跟不上 YouTube 已调整的播放器接口，拿到的是已经失效的播放地址。本次把这个组件从 2026.7.4 升到 2026.8.19。同一个视频在升级前复现失败、升级后正常下载并合并（38.7 MB），不是只看解析结果，而是真下完了文件。
- **设置页显示当前版本号**：设置 → 应用更新 区块现在会常驻显示「当前版本 v0.3.8」，就在「已是最新 / 可升级」状态旁边。此前你只能靠安装包文件名猜自己装的是哪一版。这个数字和更新器用来判断升级的版本号来自同一处，不会出现「界面显示一个版本、更新器认另一个」。

## 下载

## 边界与验证

安装包不包含 ASR 权重、密钥或用户私有配置。本地优先边界不变：视频、音频、文字稿、模型缓存与本地历史仍全部留在你自己的机器上。公开平台访问限制保持不变。macOS 沿用 ad-hoc 签名，不宣称 Apple notarization。

下载组件的升级只作用于「取媒体流」这一步，音频提取、语音识别与产物导出流程未改动。首次尝试下载字幕时仍可能遇到平台限流，程序会自动改走不带字幕的重试路径，这与上一版行为完全一致——本次没有改动这条降级逻辑。相应地，「403 / 429 这类平台侧拒绝被归入通用失败提示」的问题本次没有修，仍记为待办。

本版本面向现有个人开发与小范围用户分发，不宣称已完成干净 Windows/macOS 机器的人工桌面验收。服务端生产部署与数据库迁移不包含在本次桌面发布中。具体自动化门禁与构建结果以发布计划和 GitHub Actions 为准。
