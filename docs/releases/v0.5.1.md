# FrameQ v0.5.1

## 主要变化

- **下载卡住会自己结束**：从 YouTube、B 站等站点下载视频时，单次下载最多等待约 20 分钟。网络或代理异常导致长时间收不到数据时，FrameQ 会结束这次尝试并提示下载失败，可以直接重试，不必一直停在准备视频那一步。正常大小的视频不受影响。

- **抖音分享页的重试会进诊断包**：抖音分享页偶尔要重试一次才能解析成功，以前导出诊断包看不出区别。现在导出包里会留下一条固定的重试记录——只记录发生过重试，不保存链接、次数和等待时间——排查偶发失败时可以区分「一次就成功」和「重试后才成功」。

- **Windows 安装前先做检查**：安装程序会先看目标磁盘的剩余空间和目录写入权限。空间不够或目录写不进去时，用中文说明是哪一项没过、给出实测数字或路径，并告诉你去哪里找日志；正常安装不受影响，静默安装和自动更新也不会因为一次测量被拦下。安装过程同时写一份步骤日志（系统临时目录下的 `FrameQ-install.log`），遇到问题可以直接附上。

## 边界与验证

安装包不含语音识别权重、密钥或用户私有配置。本地优先边界不变：视频、音频、文字稿、模型缓存与本地历史仍全部留在本机。下载超时只结束本次尝试，不会删除已下载完成的文件，也不会重试消耗任何额度；诊断包只增加一条固定记录，不写入链接、请求内容或用户路径。

本次门禁：前端 1506 项通过（1 项跳过），转写服务 1276 项通过（4 项跳过），脚本测试 57 项通过，文档校验 ERROR 与 WARN 均为 0，桌面端与营销站生产构建通过，`cargo check` 通过。同时修复了一个在构建机器负载高时会误报的测试用例（不影响产品行为）。Rust 全量测试与三个平台的安装包由发布构建覆盖。

## 已知局限

- 极慢网络下的大文件下载可能被 20 分钟上限提前结束；出现时重试或换网络即可。
- 安装程序的交互提示与失败中止分支没有在真实桌面上人工点过，自动化只覆盖了静默安装路径。
- macOS 图形界面交互、首次打开时的权限与 Gatekeeper 交互，以及部分网页组件专项安全检查尚未在真机完成。
- macOS 安装包使用临时签名，未经过 Apple 公证，首次打开仍需手动放行。
- 内部验收安装包关闭了自动更新的签名校验文件，公开的签名更新链路未做端到端实测；macOS Intel 验收任务需要手动触发，不随版本标签自动运行。
- 使用 PyTorch 版语音模型的用户升级后需要重新下载一次运行时组件（约 140 MB）：组件目录与下载 URL 跟随应用版本号，v0.5.0 的组件不会被复用。默认 ONNX 模型不受影响。
